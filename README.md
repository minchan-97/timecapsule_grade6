# 타임캡슐

편지를 팻말에 걸어두면 나무가 자라고, 마지막 수업에 하나씩 열립니다.
5학년 1~4반, 6학년 1~4반이 각각 따로 굴러갑니다.

## 실행

```bash
pip install -r requirements.txt
streamlit run app.py
```

## 반 설정 (app.py 위쪽 `CLASSES`)

```python
"6-1": {"name": "6학년 1반", "code": "namu61",
        "start": date(2026, 9, 3), "open": date(2026, 12, 15)},
```

| 항목 | 설명 |
|---|---|
| `code` | 아이들이 입력하는 코드. **이 코드가 반을 결정합니다.** 8개가 겹치면 안 됩니다 |
| `start` | 편지 쓰는 날 = 0주차 |
| `open` | 마지막 수업 (개봉일) |
| `cuts` | 그 반만 다른 속도로 자라게 할 때. 생략하면 `DEFAULT_CUTS` |

아이는 반을 고르지 않습니다. 코드만 넣으면 자기 반으로 들어갑니다.
반마다 코드가 다르니 옆 반 편지는 볼 수 없습니다.

`TEACHER_PIN` 으로 들어가면 개봉 화면이고, 거기서 반을 골라 엽니다.
**배포 전에 반드시 바꾸세요.** 기본값은 `0000` 입니다.

## 나무가 자라는 시점

`start` 로부터 몇 주가 지났는지로만 결정됩니다.

| 주차 | 그림 |
|---|---|
| 0~1주 | 팻말만 |
| 2~4주 | 묘목 |
| 5~8주 | 자라는 나무 |
| 9주~ | 큰 나무 |

9월 초 시작 / 12월 중순 개봉 기준으로 **9월 중순 / 10월 초 / 11월 초** 에 바뀝니다.

한 반만 다르게 하려면 그 반에 `"cuts": (2, 4, 7)` 처럼 넣으면 됩니다.
`open` 이 9주보다 이르면 큰 나무를 못 보고 개봉합니다.

## 번호별 나무

편지 한 통이 나무 한 그루입니다. 따로 저장하지 않고 편지에서 바로 만듭니다.

- **자라는 기준**: 그 아이가 편지를 쓴 날부터. 늦게 쓰면 아직 작습니다
  (`TREE_CUTS = (3, 8)` — 0~2주 묘목 / 3~7주 자라는 중 / 8주~ 큰 나무)
- **자리**: 번호 순으로 언덕을 고르게 나누고, 번호에서 만든 값으로 조금씩 흩습니다.
  같은 번호는 언제 봐도 같은 자리입니다
- **크기**: 모두 비슷합니다(`TREE_W`). 그루가 많으면 자동으로 작아져 빽빽해지지 않습니다
- **화면 이동**: 번호를 넣으면 그 나무가 화면 가운데로 옵니다.
  모바일 세로에서는 그림판이 화면보다 훨씬 넓어 끝쪽 나무가 안 보이기 때문입니다.
  그림판 밖으로 여백이 생기지 않도록 이동 범위는 자동으로 묶입니다
- **이름 팻말**: 나무 발치에 서고, 편지에 적은 이름이 들어갑니다(다섯 글자까지).
  이름이 가리면 소용이 없으므로 팻말은 나무·꽃보다 항상 앞에 그립니다.
  크기는 `SIGN_W` 로 바꿉니다
- 교사 개봉 화면에서는 특정 나무를 키우지 않고 모두 같은 크기로 보여줍니다

## 나무 종류 고르기

다 자란 나무는 **10종** 중에 고릅니다. `우리 농장`에서 번호를 넣으면 선택창이 나옵니다.
언제든 바꿀 수 있고, 마지막에 고른 것이 적용됩니다.

묘목·중간 단계는 모든 종류가 같은 그림을 씁니다.
**고른 모습은 다 자랐을 때 나타납니다.**

`TREE_CHOICES` 에서 이름을 바꿀 수 있습니다.
폭은 `r`(세로/가로 비율)에서 거꾸로 계산해서, 모양이 달라도 **키는 모두 같습니다.**

나무를 더하려면 투명 배경 PNG 를 `static/` 에 넣고 `TREE_CHOICES` 에 한 줄 추가하면 됩니다.
`r` 은 (세로px/788) ÷ (가로px/1400) 로 계산합니다.

## 나무 돌보기

번호를 넣으면 내 나무 아래에 버튼 세 개가 나옵니다.

| 버튼 | 하는 일 |
|---|---|
| **물 주기** | 하루 한 번. 물방울이 떨어집니다 |
| **흔들기** | 잎이 떨어집니다. 기록은 남지 않습니다 |
| **열매 따기** | 다 자란 나무에만. 딴 개수가 쌓입니다 |

물은 나무를 **빨리 자라게** 합니다.
`WATER_TO_WEEK = 3` 번마다 1주씩, `WATER_BONUS_MAX = 4` 주까지.
매일 챙긴 아이의 나무가 먼저 큽니다.

열매는 `FRUIT_PER_WATER = 2` 번 물 줄 때마다 하나씩 맺힙니다.

물 주기와 열매 따기는 편지·꾸미기와 같은 기록장에 쌓입니다.
지워지지 않으니 12월에 누가 얼마나 챙겼는지 그대로 남습니다.

**손가락으로 끌어놓는 배치**는 Streamlit 커스텀 컴포넌트를 빌드해야 해서
아직 넣지 않았습니다. 지금은 슬라이더로 놓습니다.

## 농장 꾸미기

`우리 농장` 탭에서 번호를 넣으면 꽃·나비·덤불을 놓을 수 있습니다.
한 사람당 `MAX_PER_STUDENT`(기본 3)개까지.

아이템 그림은 `static/items/` 에 있습니다.
전부 배경 그림에서 잘라낸 것이라 화풍이 어긋나지 않습니다.
`ITEMS` 에서 이름·크기·놓이는 위치(하늘/땅)를 바꿀 수 있습니다.

**좌우 뒤집기**를 켜면 나비나 새가 반대편을 보게 놓입니다.

나무와 아이템은 **아래쪽에 있을수록 앞에** 그려집니다.
하늘 것(나비·새)은 자연히 뒤로 가서 나무를 가리지 않습니다.

**바람 효과**는 CSS 흔들림입니다.
배경 속 나무는 그림이라 안 움직이고, 올려놓은 것만 흔들립니다.
아이템마다 흔들리는 주기가 달라서 한꺼번에 움직이지 않습니다.

### 지우기와 백업

아이들도 **자기가 놓은 것만** 치울 수 있습니다. 남의 것은 못 건드립니다.

치워도 `data/garden_5-1.jsonl` 에서 줄이 사라지지 않습니다.
"치웠다"는 사실이 한 줄 더 붙을 뿐입니다.
화면은 기록을 처음부터 재생해서 그립니다.

그래서 교사 화면에서 **치워진 것 되돌리기**로 언제든 복구할 수 있습니다.
아이가 실수로 지웠거나 다투었을 때 원래대로 돌릴 수 있습니다.

## 그림 파일

`static/` 안의 그림은 코드가 읽어서 화면에 직접 실어 보냅니다(data URI).
Streamlit 정적 서빙 설정에 의존하지 않으므로 배포 환경을 타지 않습니다.

배경은 가로판(`stage*_wide.jpg`) 하나만 씁니다.
세로 화면에서는 가운데가 잘려 원래의 세로 그림이 그대로 보입니다.

그림을 바꾸면 이름만 맞춰 `static/` 에 덮어쓰면 됩니다.

## 관리 · 지우기 (교사용)

반을 고른 뒤 **관리 · 지우기** 를 펼치면 나옵니다.

- **편지 지우기** — 정말로 지웁니다. 되돌릴 수 없습니다.
  실수를 막으려고 `편지 지우기 켜기` 를 켜야 버튼이 눌립니다.
  지우면 그 번호의 나무도 함께 사라지고, 그 번호로 다시 쓸 수 있습니다.
- **꾸민 것 치우기** — 기록이 남아서 바로 위 `치워진 것 되돌리기` 로 복구됩니다.

## 저장

**Supabase** 에 저장합니다. 설정 방법은 `SUPABASE.md` 를 보세요.

설정이 없으면 `data/` 폴더에 임시 저장합니다.
Streamlit Community Cloud 는 앱이 잠들거나 재배포되면 이 폴더가
통째로 사라지므로, **실제 수업에서는 반드시 Supabase 를 설정해야 합니다.**
설정되지 않은 상태로 교사 화면에 들어가면 경고가 뜹니다.

바뀌는 곳은 저장 함수 네 개뿐이고 나머지 화면 코드는 그대로입니다.

편지가 저장되지 않으면 아이 화면에 오류가 그대로 표시됩니다.
조용히 사라지는 일은 없습니다.

그리고 한 달에 한 번은 반별로 **인쇄용으로 내려받기** 로 사본을 남기세요.
